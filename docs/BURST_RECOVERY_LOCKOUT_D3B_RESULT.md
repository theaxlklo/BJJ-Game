## 1. Measurement integrity record (read this first)

**One frozen run.** E-PROD, base seeds 42 and 142, 100 matches each, 300 s, stalling OFF + shadow and ON; adopted canonical controls and v1e on the same seeds and modes. No exploratory seed, extension, replacement, extra batch, tuning, exclusion or gate change.

**One scoring defect, fixed and rescored on the same preserved gameplay.** The initial scoring of the frozen run reported **G6 FAIL** and every other gate PASS. The cause was a defect in the G6 op-trace instrumentation, not in gameplay:

- The tracer keyed each match's operations by `id(match)`. CPython reused the memory addresses of finished matches, so the 100 matches of each batch were concatenated under only 3 (seed 42) or 4 (seed 142) keys. The D3-B and adopted runs did not reuse addresses in the same pattern, so the "mismatch at index 2" compared concatenations of different matches.
- **Fix (scoring only, `src/bjj_game/diagnostics/handoff_d3b.py`):** `split_op_traces` splits each preserved concatenation at terminal operations (exactly 100 complete segments per run; none open), assigns each segment to the match whose collector event log has the same post-state sequence, resolves the few identical-sequence short pre-clear matches (seed 42: {14, 59}, {39, 42, 99}; seed 142: {26, 98}) by the **unique** assignment under which match indices increase chronologically within each key (exactly 1 solution in every run, D3-B and control), and measures RNG draw counts from each match's own start. The tracer now also keeps every traced match alive, so ids cannot be reused in any later run.
- **Rescoring used only the preserved gameplay** (pickled `Runs` objects of the frozen run, sha256 `7365118586c7…` D3-B / `3a44ec14795b…` comparators). Candidate gameplay execution was blocked during rescoring; the only execution was P7's adopted canonical reference (no candidate mode; asserted), the same check the initial scoring ran.
- **Gameplay identity verified:** the rescored D3-B event logs and all proofs are identical to the initial scoring's. Gameplay code, candidate settings and gate criteria are unchanged (`git diff f92dc6e` touches only the scoring module and tests).
- **Independent confirmation of G6** using the preregistration's literal definition (D3-B event log vs the stored `fe229cb` adopted event log, through the token decision and its outcome, ignoring D3-only metadata `kind/tr/mode*/cf_action/armed` and the D3-only terminal `mode_end` marker): **0 mismatches** in all four runs; 42 token matches (25 + 17), exactly the 42 the preregistration counted.
- **Fresh reproduction:** `tests/test_d3b_measurement.py` re-executes the frozen configuration with the fixed tracer and requires the regenerated evidence file and data report to equal the committed ones.
- The initial (defective) scoring is preserved unchanged: `docs/evidence/handoff_d3b_initial_scoring_report.md` and `docs/evidence/handoff_d3b_initial_scoring_evidence.json.gz`.
